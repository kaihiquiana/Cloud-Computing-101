# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

For me, the **compute resource** is the most important component because it is what actually runs applications and processes tasks. Without CPU and memory, the other resources would not have much use because there would be nothing to process or manage the data.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a stable and flexible operating system for running servers and applications. During this activity, I was able to use simple Linux commands to check the CPU, RAM, disk, filesystem, hostname, and IP address of the cloud server. This showed me how much information can be managed and checked directly through the terminal.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it gives engineers a clear record of what resources are available before anything is deployed. It can also prevent mistakes because the team can review the server's configuration, requirements, and network setup first instead of making decisions based on assumptions.

## 4. What new skills did you learn during this laboratory activity?

I learned how to investigate a Linux cloud server using commands such as `lscpu`, `nproc`, `free`, `lsblk`, `df`, and `hostname`. I also learned more about how compute, storage, networking, and operating systems work together in cloud infrastructure. Aside from the technical side, I practiced writing Markdown documentation, researching cloud provider services, and creating a simple cloud architecture diagram.

## 5. How has your GitHub portfolio improved after completing this mission?

My GitHub portfolio became more organized and more relevant to cloud computing. Instead of only showing programming projects, it now includes an infrastructure assessment, cloud provider comparison, technical documentation, and an architecture diagram. I think this makes my portfolio more useful because it shows that I am also learning how to understand and document the infrastructure behind applications.
